The native linker also reported an undefined `facet_core::impls::core::tuple::TUPLE_TYPE_OPS` symbol. The web compiler gave a separate, concrete reason: the existing `vendored` crate requested a `dylib`, which `wasm32-unknown-unknown` cannot produce. The agent also cited the unfinished web host in its revision rationale. The compiler diagnostic establishes the crate-type failure directly.

**What changed.** The agent used the existing opaque asset metadata convention, paired activation reports with the intent they described, and corrected session-directory fixture ownership. The revision changed the static Game server crate type to `rlib` so its native dependencies could link the Facet statics. It removed `build-game-web` from the authored checks and added a manual inspection of Cargo’s resolved graphs: the wasm32 Game client must exclude `SnapshotPlugin`, native hot launchers must omit app libraries, and static launchers must link them. Revision 6 subsequently passed typechecking and the static server build. The graph inspection eventually passed under revision 8. A successful web compilation remained unproven. **Handling and recommendation.** The existing Resolve and review flow did the right thing here. A compile repair within the accepted API can stay in Resolve. The useful improvement is to headline the decision in the approval prompt: **“Replace the required Game web build with a check that wasm32 excludes SnapshotPlugin.”** Show the original compiler error and the lost build guarantee alongside it. If a working web binary is a release requirement, retain the build and address the dependency or track it as blocked.

## Revision 7 · Formatting scope and the formatter helper

**What prompted review.** The agent requested formatting on 65 paths and reported that the apply edited 36 Rust files. The Ferrous helper had temporarily gained a scoped apply branch. Forge separately derived a required read-only verification from that mutation and widened its selection to the whole workspace. The resulting failure included 18 unformatted files outside the requested selection. This put the user in the position of approving unrelated formatting edits or waiting for a Harness fix.

**What the revision changed.** Revision 7 removed `format` from the plan’s automatic check list and added a manual action requiring the saved formatter check on added and modified Rust files in the refactor. It also reconciled a private `System` alias with the already-approved `ManagedSystem` field type. The user approved the revision, but the older mutation still carried its historical helper digest. Restoring the original `.forge/checks/rust.nu` caused Forge to block two attempts before checks ran. Restoring the checkpointed helper allowed checking to proceed and exposed the workspace-wide failure again. Approval had changed the plan without clearing that independent obligation. [Submitted revision 7](../.local/share/nvim-data/forge/harness/state/v77/plans/b01225fd-1bc4-4820-b174-80352309bbf6/3fabb516-62e3-42f7-a42a-32fdf8633770/revisions/submitted-0007.md)

**Handling added in Forge.** Commit `8b9031f2` removed mutation-derived follow-up checks from planned execution. A past format or lint apply no longer injects a check, forces an `All` selection, or requires restoring its historical helper just to proceed. Planned checking runs the checks selected in the plan, checks that own requested test cases, reviewer-selected suites, and their declared prerequisites. A deliberately selected whole-workspace check can still report workspace-wide drift. [Check selection](nvim/docs/forge/checks.md) · [Verification record handling](nvim/rust/forge/crates/forge-harness/src/checks/verification.rs)

**Handling added in Ferrous.** Commit `af17162a` made `format_apply` and `format_check` honor the same explicit Rust files. A selected source file covers only itself, even if it declares child modules. Directory selections cover Git-visible Rust sources below the directory. A member manifest selects its Cargo package, and the workspace manifest or shared formatter configuration selects its configured workspace. The adapter reports manifest and configuration widening. The regression fixture applies to one file, checks that same file successfully, and verifies that an unrelated unformatted file stays untouched. These changes address the two causes of revision 7. The session itself finished by manually verifying its 65-file selection. [Ferrous adapter](../code/ferrous/main/.forge/checks/rust.nu) · [Regression fixture](../code/ferrous/main/.forge/tests/rust-format.nu)

## Revision 8 · Equivalent Rust exports and a missing test

**Why the audit objected.** Rustfmt folded the separate `pub use archive::WorldArchive` into an existing grouped public re-export. The exported path, name, and visibility stayed the same. Forge compared the declaration forms and reported two expected declarations missing and one additional declaration. The author could satisfy the audit by changing the plan to match rustfmt’s grouping, even though users of the API saw no change.

**Why passing tests were insufficient.** The plan listed `initialization_failure_fixture` in `engine/host/tests/launch_sessions.rs`. It is an ignored subprocess helper. The runnable parent, `failed_initialization_can_retry_after_filesystem_repair`, drives the failure and checks recovery. The selected run reported 26 passing tests, but Forge could not resolve the planned fixture name in the executable inventory. That coverage failure identified a real mistake in the plan.

**What changed and what remains.** Revision 8 adopted the grouped export and selected the runnable parent test. Auto-accept applied the revision. The agent then reported that its immediate phase transition used stale task authority after acceptance. A subsequent exchange continued against revision 8. The automated gate passed, followed by the native Browser reload, Cargo dependency-graph inspection, and scoped formatting verification. The corrected plan resolved this session. No general change for re-export equivalence or fixture-name selection was added as part of these fixes. [Submitted revision 8](../.local/share/nvim-data/forge/harness/state/v77/plans/b01225fd-1bc4-4820-b174-80352309bbf6/3fabb516-62e3-42f7-a42a-32fdf8633770/revisions/submitted-0008.md)

**Suggested handling.** Compare Rust re-exports by resolved path, exposed name or alias, visibility, and conditional attributes. Cover grouping and ordering changes with a regression test, alongside cases where an alias or visibility really changes. For reused tests that already exist, flag an unresolvable selector during review when discovery evidence is available, and show the file and discoverable candidates. Keep execution-time discovery authoritative for new tests that the implementation has yet to create. Preserve the stale-authority guard after auto-accept, and tell the agent to continue against the newly accepted revision.
