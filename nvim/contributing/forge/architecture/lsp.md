# Agent LSP tools

A stale or partial language-server answer can mislead an agent into a wrong edit, and a query that reads unauthorized files would bypass Harness permissions. Rust therefore authorizes every target before the editor reads it, and every result reports its coverage, so an incomplete answer never reads as a clean one.

The [tool reference](../../../docs/forge/lsp-tools.md) defines arguments and formatting. This chapter covers how the tools work.

## Request flow

Eleven read-only `lsp_*` tools expose source overview, symbol discovery, navigation, context, references, calls, call paths, diagnostics, and status. `SourceDeclaration` extraction for Rust, TypeScript, JavaScript, and Lua supplies source ranges, signatures, nesting, and visibility, separately from plan projection.

Rust owns one interaction scope per root or child turn, with the read policy and setting generation. It admits at most four requests per host, each with a five-minute startup/readiness allowance and a 30-second semantic-query deadline. The host response deadline includes these allowances and a delivery margin. Correlated `lsp.request` events reach the editor regardless of the selected view, and `session.lsp.authorize`, `session.lsp.respond`, and `session.lsp.analyze` bypass the busy broker lock. Target authorization precedes every editor read, and Rust checks returned paths again before publishing text. Cancellation sends `lsp.cancel`, and late replies cannot revive the request.

## Editor adapter

The shared Lua adapter owns client selection, hidden source buffers, and reference-counted leases. Agent queries read live editor contents, while plan navigation rejects source that differs from its captured digest. Unused hidden buffers expire 60 seconds after their last request.

`forge.lsp.workspace` discovers project directories with language keys (`rust`, `typescript`, and `lua`) without starting servers. Semantic requests carry `{ path, language }`; Rust authorizes the directory, and Lua selects one enabled Neovim configuration for that language. A sole matching configuration is selected automatically; `lsp.workspace_servers.rust`, `.typescript`, and `.lua` name preferred existing configurations when multiple configurations match. Ambiguity fails before startup. One selected client remains bound through target resolution, follow-up queries, diagnostics, and rename preparation; no operation combines servers. File requests reject mismatched languages or uncovered paths before contacting the selected client. Source paths remain relative to the session repository.

`forge.lsp.startup` starts only the selected configuration for semantic requests. Overview, source-scoped symbol listings, and context with a local target parse authorized source directly. Context without workspace performs no semantic requests. Context with workspace may add hover from the selected server. Semantic operations own readiness checks, scoped by path and supported method; a request remembers ready clients across target resolution and subsequent lookups. Each new request checks readiness again. Query deadlines include the five-minute startup allowance.

Project discovery lists nested Cargo.toml and package.json directories outside dependency, build, cache, and nested Git directories. Lua discovery resolves authorized Lua files through `forge.lsp.root`, which shares Neovim's configured marker precedence or asynchronous root callback with startup. Static marker resolution runs once per source directory; custom callbacks run per file. Discovery deduplicates Lua roots, authorizes each resolved root, and reports missing roots or unavailable configurations explicitly. Temporary callback buffers are removed when discovery settles or is cancelled unless the user has edited or displayed them. Semantic startup resolves the selected project's manifest or Lua source through one enabled configuration. Lua startup requires the resolved root to match the selected directory, so a parent client cannot replace a nested Lua workspace.

Unless that configuration supplies `cmd_cwd`, the server process starts in its resolved root so project-local launchers such as Rustup select the project toolchain. Duplicate matching clients are an error. Acquisition first reuses a matching editor-owned client, including one started by opening a file, without rerunning its root resolver. `startup.ready` is the common readiness boundary for acquisition, every semantic request, and direct rename messages. It retains client identity, waits for initialization and indexing, and completes once on readiness, timeout, or disconnection; cancellation suppresses delivery. Root resolution uses the startup allowance rather than a separate short discovery cutoff. Rust readiness additionally requires an observed `experimental/serverStatus` with quiescence; an empty progress queue alone does not establish that the workspace is loaded. Forge installs observation during setup and chains existing global and client-specific handlers. Missing status remains pending until timeout, never a successful empty query. Quiescent warnings allow read queries and are preserved in the reply, while fatal health errors reject them. Name-only resolution remains incomplete when a warning prevents proving uniqueness, and renames reject known incomplete workspace analysis. Concurrent requests reuse the same startup job and wait for initialization and reported indexing to finish. Cancelled waiters do not stop editor-owned servers. Startup completion and query readiness are distinct: a completed startup job whose client reports indexing keeps the tool request pending until indexing finishes or the readiness deadline expires. Project discovery continues through asynchronous filesystem callbacks without a timer delay per directory.

## Result accuracy

`forge.lsp.target` resolves names and occurrences, failing on ambiguity or incomplete search before the semantic operation starts. `forge.lsp.paths` walks outgoing call hierarchy edges with cycle checks, and captures every visited file so any change invalidates the result.

`forge.lsp.diagnostics` reuses a document pull report only while its buffer tick and client generation match. For workspace diagnostics it prefers native `workspace/diagnostic` when the selected server advertises support; otherwise it reads Neovim's push namespace for that live client, including reports for unopened files. Neovim owns report replacement and clearing. Forge neither duplicates that cache nor includes document-pull namespaces or retired clients.

Workspace diagnostic results stay within the selected client's resolved root, including when selection starts from a nested manifest. The semantic adapter authorizes reported paths before reading source or exposing messages, then applies severity filtering and pagination. Published snapshots carry partial coverage and unknown freshness, even when empty; native workspace reports retain their response validation and coverage reporting. Collection never opens files to provoke diagnostics, requests diagnostics per file, or triggers compiler checks or refresh notifications. An empty published snapshot establishes only that the client currently has no matching published reports, not that the workspace is clean. Unsupported acquisition, startup failure, and disconnected servers remain explicit failures.

## Rename ownership

`lsp_rename_symbol` and `lsp_rename_file` use the dedicated `lsp.mutation` event. Mutation replies transfer their complete JSON in ordered chunks through `session.lsp.respond`; list pagination never limits a workspace edit. Rust retains correlation, turn authority, directory permissions, and a host-wide mutation gate. Lua resolves targets, requests server edits, validates buffer versions, and holds affected clean buffers until Rust releases preparation.

Rust stages the complete filesystem result and its original bytes and modes before committing. Every affected resource is authorized using the invocation's directory policy and captured permission rules. Renames require existing permission and never request approval. Commit owns recovery until it settles even if the provider waiter is cancelled. Lua refreshes buffers and sends post-operation notifications only after commit. Native tool addresses receive the normalized change set through the existing provider event stream, preserving timeline and checkpoint attribution.

Read-only interaction modes exclude both tools at advertisement and execution. Every conversation's open-time instructions include `src/prompts/lsp.md`, which tells the model to prefer LSP tools over text search when they are available. The guidance is the same whether or not the tools are enabled; each turn's tool definitions show their availability ([Turn context](providers.md#turn-context)).
