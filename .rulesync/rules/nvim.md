# Neovim Configuration

Use the `neovim-lua-dev` skill for all Lua and Neovim plugin work. It owns cursor and selection preservation, live-editor safety, LuaLS annotations, asynchronous processes, and failure notifications.

- **Persisted data:** Backward compatibility is not a goal for disposable state. Never migrate incompatible sessions, transcripts, caches, or journals; select a fresh compatibility-version directory and provide cleanup for obsolete versions without blocking new versions on old editors. Preserve user settings and configuration outside that namespace and try to migrate them gracefully, reporting unsupported formats and failures. Reuse the owning store's cleanup boundary, protect whole versions held by live users, and leave unrelated files untouched.
- **Test layout:** Each plugin keeps its tests in `nvim/lua/<plugin>/tests/`, and every test file ends in `.test.lua` and returns a mini.test `MiniTest.new_set()`; load the `mini-test` skill before writing one. Unit tests live under `tests/unit/` and integration tests under `tests/integration/`; both mirror the plugin's source tree. Shared helpers live in `tests/support/`, test data and manual scripts in `tests/fixtures/`, and notes in `tests/plans/`. These are plain `.lua` or Markdown files and never run as tests.
- **Unit tests:** A test of one source file's behavior is a unit test, at that file's mirrored path: `nvim/lua/forge/views/status/status_context.lua` → `nvim/lua/forge/tests/unit/views/status/status_context.test.lua`, and `init.lua` → `init.test.lua`. Each test is a top-level case, `T["name"] = function() ... end` at column zero, which is how the runner discovers cases. Add a new unit test as a case in the existing file, never as a separate file. When a source file moves or is renamed, move its unit test file to the matching path.
- **Isolation and cleanup:** A unit test file runs as one shard, its cases in sequence in one Neovim, so its set uses `dofile("nvim/lua/forge/tests/support/isolation.lua").hooks({ post_case = ... })`, which restores the editor and unloads every plugin module after each case. Require plugin modules inside cases or hooks, never at file scope. Register cleanup with `MiniTest.finally`, wrap fallible cleanup in `pcall` because mini.test runs those callbacks unprotected, and call helpers that register a `finally` from the case body, because a `finally` registered in a hook runs when the hook returns. Use `MiniTest.expect.equality` and `MiniTest.expect.error` instead of hand-written assertion helpers, and use the shared helpers in `tests/support/` (`wait.lua`, `buffer.lua`, `keymap.lua`, `temp.lua`, `stub.lua`, `notify.lua`, `mock_client.lua`, `host.lua`, `git_repository.lua`) instead of local copies; `nvim/contributing/forge/editor-tests.md` describes each.
- **Integration tests:** A test that drives several modules together, the Forge host, or Git is an integration test. It is a case in the file named after the source area it exercises, in that area's mirrored directory: `views/status/` → `nvim/lua/forge/tests/integration/views/status/status.test.lua`, and a top-level module's area is a directory named after it, such as `integration/client/client.test.lua` for `client.lua`. Add a new integration test as a case in its area's file; each top-level case runs in its own Neovim. Only a test that must reload its own file in a child Neovim, or that shares a heavy `pre_once` setup across its cases, stays a standalone file in the area directory. A self-relaunching file checks a `vim.g` child flag before `require("mini.test")`, runs its child body, and returns, and never dispatches on `arg`. Load helpers by repository path, such as `dofile("nvim/lua/forge/tests/support/state.lua")`, at file scope before the test changes directory.
- **Running Lua tests:** Run Lua tests only through `.forge/checks/lua-tests.nu`, never a hand-written `nvim -l` command. Tests that launch the Forge host assume a current executable, so run `rust-build` after Rust changes and before the Lua tests. Unit shards and integration cases run in parallel, each in its own headless Neovim. Every case fails at five seconds, and a unit shard is killed after one minute. Select tests by test file, source file, directory, test name (the file name without `.test.lua`, which selects every file with that name), or `name::case`. A source directory selects both of its mirrors:

  ```nu
  nu .forge/checks/lua-tests.nu                                   # every test
  nu .forge/checks/lua-tests.nu client                            # unit/client.test.lua and integration/client/client.test.lua
  nu .forge/checks/lua-tests.nu client::admission_queue           # one case
  nu .forge/checks/lua-tests.nu nvim/lua/forge/client.lua         # a source file's unit test
  nu .forge/checks/lua-tests.nu nvim/lua/forge/lsp                # unit and integration tests for lsp/
  nu .forge/checks/lua-tests.nu --suite status                    # a source area's unit and integration tests
  nu .forge/checks/lua-tests.nu --affected nvim/lua/forge/client.lua  # tests covering changed paths
  nu .forge/checks/lua-tests.nu --filter 'harper|wordlist'        # cases whose path::case matches a regex
  nu .forge/checks/lua-tests.nu client --filter queue             # narrow any selection by the same regex
  nu .forge/checks/lua-tests.nu --list client                     # print the selection without running it
  ```

  `--affected` runs a changed source file's mirrored unit test plus its integration area (the nearest mirrored integration directory of the file or an ancestor), or the plugin's whole test directory when it has no area; a change under `tests/` or to the runner runs every test.
- **LuaLS check:** Check the whole plugin with `lua-language-server --check nvim/lua/forge --logpath <scratch directory outside the repository>`, using the scoop build, because the Mason build crashes on `--check`. After a refactor that moves files with `git mv`, run `:LspRestart` to clear duplicate warnings from the stale index.
